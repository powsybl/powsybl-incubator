# PowSyBl Network Editor

[![MPL-2.0 License](https://img.shields.io/badge/license-MPL_2.0-blue.svg)](https://www.mozilla.org/en-US/MPL/2.0/)
[![Slack](https://img.shields.io/badge/slack-powsybl-blueviolet.svg?logo=slack)](https://join.slack.com/t/powsybl/shared_invite/zt-36jvd725u-cnquPgZb6kpjH8SKh~FWHQ)

TypeScript component adding interactive editing to the single-line diagrams (SLD) displayed by
[powsybl-network-viewer](https://github.com/powsybl/powsybl-network-viewer) and generated by
[powsybl-diagram](https://github.com/powsybl/powsybl-diagram).

The editor **never mutates the network**. Every user edit is recorded as an undoable command, previewed in the diagram,
and exposed as a **change set**: a normalized list of network modifications, in the format of
[gridsuite-network-modification](https://github.com/gridsuite/network-modification), that the host application sends to
its backend.

```
powsybl-diagram ──► SVG + metadata ──► NetworkEditor ──► change set (NetworkModification[]) ──► host backend
                                            ▲    │                                              │
                              host menus/forms   └── events                     applies it, redraws the SLD
```

## Features

- **Selection** of equipments: click, `Shift` + click for multi-selection.
- **Creation** of:
  - injections (load, generator, battery, shunt compensator, static var compensator, VSC/LCC converter stations,
    boundary line) as a new feeder bay on a busbar, on a free node, or behind a new switch;
  - switches between two nodes;
  - busbars, below the existing ones;
  - couplings between two busbars of the same section.
- **Deletion** of equipments and whole bays, **replacement** of an injection by another type, **renaming**, **property
  update**.
- **Bay layout**: move a bay to another busbar, change its position, flip its direction.
- **Previews drawn like powsybl-diagram**: pending creations use the SLD component symbols, bays are reflowed along the
  busbars, an equipment added on a node that already has a branch forks off into its own column.
- **Undo / redo**, one command per user gesture.
- **Change set** export, normalized: a creation followed by a deletion cancels out, renames and property edits of a
  created equipment are folded into its creation.
- **Framework-agnostic and headless**: no React, no UI. The editor describes the available actions; the host renders
  menus and forms with its own design system.

## Requirements

| Requirement | Why |
|---|---|
| A browser (DOM + SVG) | The editor works on the SVG rendered in the page. |
| [`@powsybl/network-viewer-core`](https://github.com/powsybl/powsybl-network-viewer) `^3.8.0-dev.0` (peer dependency) | Displays the SLD and provides the SLD component library (`createSldComponentElement`, `DefaultSldLibraryComponents`) used to draw previews. Not released yet: branch `cl-sld-viewer-expose-component-library`. |
| SLD SVG and metadata from [powsybl-diagram](https://github.com/powsybl/powsybl-diagram), **with IIDM node metadata** | The editor maps diagram nodes to IIDM nodes (`iidmNode`, `iidmNode1`, `iidmNode2`) and busbars to their position (`busbarIndex`, `sectionIndex`). Without them, nodes and busbars are not editable. Not released yet: branch `cl-sld-metadata-extension`. |
| A backend applying the change set | For instance one built on [gridsuite-network-modification](https://github.com/gridsuite/network-modification). See [Operations and change set](#operations-and-change-set) for the supported types. |

```bash
cd network-editor
npm install

```

## Quick start

```ts
import {
    NetworkEditor,
    groupMenuItems,
    type ActionMenuItem,
    type SLDMetadata,
} from '@powsybl/network-editor';

const editor = new NetworkEditor({
    container: document.getElementById('diagram')!,
    svgContent,                         // SLD SVG produced by powsybl-diagram
    metadata: metadata as SLDMetadata,  // matching SLD metadata
    initialProperties,                  // optional: equipment properties by id
    onEvent: (event) => {
        switch (event.name) {
            case 'menu:requested':      // right-click on an editable target
                showMenu(groupMenuItems(event.items), event.position);
                break;
            case 'gesture:changed':     // an action needs a form (or a gesture ended)
                if (event.action) showForm(event.action);
                break;
            case 'modifications:changed':
                showChangeSet(event.modifications);
                break;
        }
    },
});

function onItemClicked(item: ActionMenuItem): void {
    if (item.needsForm) showForm(item.action);  // the host form calls item.action.run(values)
    else item.action.run();
}

// When the user validates the edits
await backend.apply(editor.getModifications());
editor.destroy();                       // then redraw the SLD returned by the backend
```

Two complete integrations:

- [`demo/App.tsx`](demo/App.tsx): standalone demo, with a context menu (`demo/ContextMenu.tsx`) and a generic form
  built from `action.form` (`demo/PropertyForm.tsx`);
- [`network-editor-demo`](https://github.com/powsybl/powsybl-incubator/tree/network-editor-demo/network-editor-demo): React application with
  a Spring Boot backend applying the change set with gridsuite-network-modification.

## API

Everything exported by [`src/index.ts`](src/index.ts) is public; anything else is internal.

### Options

| Option               | Type                                  | Default           | Description |
|----------------------|---------------------------------------|-------------------|-------------|
| `container`          | `HTMLElement`                         | —                 | Element hosting the diagram (required). |
| `svgContent`         | `string`                              | —                 | SLD SVG content (required). |
| `metadata`           | `SLDMetadata`                         | —                 | SLD metadata (required), see [Requirements](#requirements). |
| `svgType`            | `string`                              | `'voltage-level'` | Diagram type passed to the viewer. |
| `minWidth`           | `number`                              | `200`             | Minimum diagram width. |
| `minHeight`          | `number`                              | `200`             | Minimum diagram height. |
| `maxWidth`           | `number`                              | `2000`            | Maximum diagram width. |
| `maxHeight`          | `number`                              | `2000`            | Maximum diagram height. |
| `selectionBackColor` | `string`                              | `'white'`         | Background color used by the viewer for selection. |
| `callbacks`          | `ViewerCallbacks`                     | —                 | Viewer callbacks (`onNextVoltage`, `onBreaker`, `onFeeder`, `onBus`, `onToggleHover`), called when the editor has no action for the clicked target. |
| `onEvent`            | `(event: EditorEvent) => void`        | —                 | Listener receiving every editor event. |
| `initialProperties`  | `Record<string, EquipmentProperties>` | —                 | Initial equipment properties, by equipment id: they fill the edit forms. |
| `isSupported`        | `(action: EditorAction) => boolean`   | —                 | Filters the actions offered to the user, e.g. those the host backend cannot apply. |

### Methods

| Method                          | Description |
|---------------------------------|-------------|
| `undo()` / `redo()`             | Undo or redo the last command. |
| `getModifications()`            | Returns the pending change set as `NetworkModification[]`. |
| `clearModifications()`          | Reverts every pending command and clears the history. |
| `cancelGesture()`               | Cancels the gesture in progress (also triggered by `Esc`). |
| `showIidmNodes(enabled)`        | Toggles the IIDM node debug overlay. |
| `getViewBox()` / `setViewBox()` | Reads or sets the diagram view box. |
| `getWidth()` / `getHeight()`    | Diagram dimensions. |
| `destroy()`                     | Removes listeners and clears the container. |

Creating a new editor on a container that already hosts one destroys the previous instance.

### Events

Events are delivered to `onEvent` as `{ name, ...payload }`:

| Event                   | Payload                                 | When |
|-------------------------|-----------------------------------------|------|
| `element:selected`      | `{ elements }`                          | The selection changed. |
| `history:changed`       | `{ canUndo, canRedo }`                  | The undo/redo stack changed. |
| `modifications:changed` | `{ modifications }`                     | The pending change set changed. |
| `gesture:changed`       | `{ gesture, action }`                   | A gesture started, progressed or ended (e.g. picking the second end of a switch, sliding a bay). `action` is set when a form must be shown. |
| `menu:requested`        | `{ items, targets, trigger, position }` | The user clicked or right-clicked an editable target. |

### Actions, menus and forms

The editor offers **actions** (`EditorAction`); the host decides how to show them.

| `EditorAction` field | Description |
|---|---|
| `operation`, `subject` | What the action does (`EditOperation`) and on what (an element type, a destination busbar, a selection size). |
| `form`               | `PropertyDescriptor[]` describing the fields to ask (`key`, `type`, `options`, `required`, `min`, `max`, `unit`, `readOnly`…). Empty when no form is needed. |
| `initial`            | Initial form values. For a feeder bay creation or a property update, it is the very GridSuite modification the action would produce, so a GridSuite dialog can open on it. |
| `equipment`          | The equipment the action applies to, if any. |
| `run(values?)`       | Applies the action with the form values. Returns `false` when refused (invalid values, id already taken…). |

Helpers to build menus:

| Export | Description |
|---|---|
| `ActionMenuItem` | `{ action, label, danger, needsForm }`, as sent by `menu:requested`. |
| `groupMenuItems(items)` | Groups the items by operation, dangerous ones last: an operation with several variants (e.g. *Add injection ▸ LOAD, GENERATOR…*) can be shown as a submenu. |
| `actionLabel(action)`, `operationLabel(operation)` | Default English labels. |
| `describeTargets(targets)` | Short description of the clicked targets, for a menu header. |
| `actionKey(action)` | Stable key such as `CREATE_FEEDER_BAY:LOAD`, to map an action to a host form or translation. |

## Operations and change set

Each operation produces one entry of the change set. The format follows the DTOs of gridsuite-network-modification
(`ModificationInfos`); some types only exist in its fork
[`clementleclercRTE/network-modification`](https://github.com/clementleclercRTE/network-modification) (branch
`network-editor`), and some have no backend support yet.

| Operation | Target | Modification | Backend support |
|---|---|---|---|
| `CREATE_FEEDER_BAY` | busbar | `LOAD_CREATION`, `GENERATOR_CREATION`, `BATTERY_CREATION`, `SHUNT_COMPENSATOR_CREATION`, `STATIC_VAR_COMPENSATOR_CREATION`, `CONVERTER_STATION_CREATION`, `LCC_CONVERTER_STATION_CREATION`, `BOUNDARY_LINE_CREATION` | GridSuite |
| `CREATE_INJECTION` | free node | `NODE_INJECTION_CREATION` | none yet |
| `CREATE_SWITCHED_INJECTION` | node | `SWITCHED_INJECTION_CREATION` | none yet |
| `CREATE_SWITCH` | two nodes | `SWITCH_CREATION` | fork |
| `CREATE_BUSBAR` | busbar | `BUSBAR_CREATION` | fork |
| `CREATE_COUPLING` | two busbars | `CREATE_COUPLING_DEVICE` | GridSuite |
| `DELETE_BAY` | equipment | `EQUIPMENT_DELETION` | GridSuite |
| `DELETE` | equipment | `ELEMENT_DELETION` | none yet |
| `REPLACE` | injection | `EQUIPMENT_DELETION` + creation (`*_CREATION`, or `NODE_INJECTION_CREATION` off a busbar bay) | GridSuite / none yet |
| `RENAME` | equipment, busbar | `EQUIPMENT_RENAME` | fork |
| `UPDATE_PROPERTIES` | equipment | `*_MODIFICATION`; `EQUIPMENT_ATTRIBUTE_MODIFICATION` for a switch state | GridSuite |
| `MOVE_BAY`, `UPDATE_BAY_POSITION`, `FLIP_BAY_DIRECTION` | bay | `MOVE_VOLTAGE_LEVEL_FEEDER_BAYS` | GridSuite |

Use `isSupported` to hide the operations your backend cannot apply.

## Styling

The editor injects its own styles. Colors can be themed with CSS variables on the container:

| Variable | Used for |
|---|---|
| `--ne-accent`, `--ne-accent-soft`, `--ne-accent-hover`, `--ne-accent-strong` | Pending creations and their labels. |
| `--ne-selection` | Selected equipments. |
| `--ne-candidate`, `--ne-candidate-strong` | Candidates during a gesture (switch ends, bay slots). |
| `--ne-halo` | Halo around highlighted elements. |

Main CSS classes: `ne-selected`, `ne-pending-create`, `ne-node-target`, `ne-switch-start`, `ne-switch-end`,
`ne-bay-slot`.

## Development

```bash
npm install
npm run dev    # standalone demo (Vite), on demo/data/reseau.{svg,_metadata.json,_properties.json}
npm run check  # type-check (src + demo)
npm run test   # unit tests (Vitest, jsdom)
npm run build  # library build into dist/
```

`@powsybl/network-viewer-core` is linked as a `file:` dev dependency to a local build of powsybl-network-viewer: build
that package first.

Conventions: strict TypeScript, every edit goes through a reversible command, every SVG access through
`SvgDomService`, the SLD metadata is never mutated, the change set format stays aligned with the gridsuite DTOs. Tests
live next to the tested file (`*.test.ts`).

## Project structure

```
src/
├── actions/        # editor actions, operations, menu helpers, property descriptors
├── commands/       # undoable commands (create, delete, rename, replace, move bay…)
├── dom/            # SVG DOM access, preview shapes and editor styles
├── editor/         # NetworkEditor (public facade), EditorCore, PendingPainter (previews)
├── layout/         # bay reflow, forks and diagram geometry
├── model/          # editor model built from the SLD metadata
├── modifications/  # change set types and normalization
├── types.ts        # shared types and constants
└── index.ts        # public API
demo/               # standalone React demo
docs/               # design notes (in French)
```
